# Working in Still

This repository is the standalone service-site starter. Follow the source ownership
in [README.md](README.md): shared library fixes and producer qualification belong in
their specialist repositories. Preserve consumer content, scoped notices, retained
vendor archives and published history. Use [package.json](package.json) and README
for the supported runtime and commands, and [UPGRADING.md](UPGRADING.md) for library
or starter-tooling changes.

Recover the current authorized scope and holds from the task before continuing.
Keep one writer per candidate and coordinate overlapping file changes. Preserve
compatible checkouts, dependency installations and build caches. Before using cached
tools or output as current-candidate product evidence, reconcile the manifest,
lockfile, delivery receipt/archive hashes and installed dependencies. Follow the
documented frozen-install procedure when product qualification requires refreshed
dependencies; instruction or metadata changes alone do not require product replay.

Use focused challenges for unresolved questions. When an independent agent reviewer
is needed, use a subagent inside the working session. Do not transfer review to a
separate executor or assume optional ub-review capacity. Preserve valid earlier
reviews and their original candidate identities. Refresh affected evidence when its
inputs or assumptions change, and complete all currently required reviews and checks.

Record candidate commit/tree, relevant archive digests, environment, commands and
outcomes in the existing task or PR record. Label historical or carried-forward
evidence with its original run and subject; do not claim it as a fresh candidate pass.
Keep [STARTER-DELIVERY.json](STARTER-DELIVERY.json) and
[SOURCE-PROVENANCE.json](SOURCE-PROVENANCE.json) as scoped delivery records, rather
than session journals. Before reset, save a recoverable checkpoint in the existing
task/PR record or an authorized durable artifact: checkout identity, current scope
and holds, committed and uncommitted changes, evidence locations, next owner/action,
and remaining work or blockers. A local-only path is not delivered evidence; verify
receiver access before claiming a handoff is complete. For a blocked operation,
record its exact action/target, reason and denied, pending or uncertain outcome;
check an uncertain outcome before retrying and never use another route to evade denial.

Inspect [.github/workflows/starter.yml](.github/workflows/starter.yml) and current
repository requirements to establish which candidate is actually qualified.
Qualification of composed merge-queue candidates is the desired direction; verify
its implementation before claiming it is deployed or relying on it for integration.
Preserve required checks, approvals and security controls. Local output, browser
acceptance, hosted acceptance and deployment approval remain distinct as documented
in README and STARTER-DELIVERY; local acceptance does not grant deployment approval.

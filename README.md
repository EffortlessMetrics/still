# Still service-site starter

A neutral, standalone default with verified offline caching and connection-aware native intent prefetch enabled. Shared components keep their established npm names/imports; canonical static precache setup uses the unpublished astromache 0.2.6 core preset. Cache integrity and lifecycle remain owned by offline 0.1.5. The exact shared vendored candidate also serves explicit `/index.html` navigations from verified directory pages; the prior archive is retained for rollback.

Use Node 24.19.x. Run `npm ci --ignore-scripts`, `npm run check`, `npm run build`, `npm run verify:starter`, `npm run verify:licenses`, `npm run test:licenses` and `npm run test:starter`. Use `npm run dev` for local editing or `npm run preview` to inspect the static build. Exact active archive hashes are in STARTER-DELIVERY.json. These expanded candidates are not yet registry releases.

Edit `site.config.mjs` for the public origin, site name, navigation, footer link, theme storage key and offline policy. Replace page prose in `src/pages/`, styling in `src/styles/starter.css` and the favicon in `public/`. Configuration is public and may be bundled into browser code. Keep API and host redirect URLs out of the precache using excludedPages and excludedPrefixes. Query policy is explicitly stripQuery:false. Registration follows site.offline.workerFile at root scope; edit that setting to rename the generated and registered worker together, and update the worker path in public/_headers to preserve its no-cache policy. Scope remains configured in the small layout registration call. Natural activation waits for existing clients; no forced reload or activation occurs.

The workshop and project-support examples opt in to the shared `ServiceColumns` treatment with `class="service-dividers"`: generous desktop gutters and faint dotted separators that fade at both ends, becoming horizontal between stacked mobile offers. Remove that class to use plain open columns. To restore cards, also add `class="offer"` to each `ServiceOffer`. This choice belongs to your editable pages; it does not change the default shared components or require you to retain either example route. Divider styles come from the pinned Still library, so adopt its qualified delivery rather than copying producer CSS into the starter.

Builds default to preview indexing policy: every page uses `noindex,nofollow` and `robots.txt` disallows crawling. After replacing the example origin and content, build for an indexable production site with `PUBLIC_SITE_ENV=production npm run build`, then run `PUBLIC_SITE_ENV=production npm run verify:starter`. Set the same environment variable in your host's build configuration. `npm run preview` serves the policy already emitted by the build. This flag does not approve deployment or supply a contact service; the sample form remains disabled.

Add, rename or remove routes in `src/pages/` and update your navigation, footer and page links. The build generates `sitemap.xml` from emitted HTML, including generated dynamic routes. It excludes 404 pages, host redirect paths in `site.offline.excludedPages` and the optional `site.sitemapExcludedPaths` list; the default list excludes the informational offline page. Keep that list current if you rename the fallback. Sitemap generation runs before offline generation so its final bytes can also be precached. Sitemap output is generated during builds; use `npm run preview` to inspect it. `verify:starter` checks the actual output and resolves a custom string `outDir` through Astro configuration. It requires at least one page, without requiring the sample services or contact route. Keep the configured offline fallback in the precache; a smaller site may use its home page as the fallback.

The pinned offline integration selects directory pages ending in `index.html`. Use Astro's default directory output for offline reading. `build.format: 'file'` routes and other standalone HTML files in `public/` are discovered for the sitemap, but are not automatically precached by this integration. `verify:starter` checks the worker's actual install entries against its receipt and diagnostic digests, rejects duplicate normalized URLs, and requires each eligible emitted page's runtime digest to match its emitted bytes. It also checks the effective worker policy, cache ownership prefix, receipt revision and excluded page corpus against your configuration and worker. Convert unsupported pages to directory output, or deliberately exclude a route in `site.offline.excludedPages` or a prefix in `site.offline.worker.excludedPrefixes` when offline reading is not intended. A sitemap exclusion alone does not waive offline coverage. Rebuild after editing output or offline policy so the generated worker and receipt match; verification is local output evidence and does not replace hosted lifecycle checks.

The disabled demo form is marked `data-starter-contact-example`. Its safety checks apply wherever that marked example appears. Replace it with your contact details or remove the page freely. When implementing your own contact service, remove the demo marker and supply your own submission, privacy and acceptance checks. Keeping the marker requires the demo to remain without an action or form ID and every input, button and textarea to have its own `disabled` attribute, even inside the disabled fieldset. This also covers controls moved outside that fieldset or into its first legend; omitting a form ID prevents outside controls from associating with the demo. Retained demos use ordinary text wrappers, fieldsets, labels, inputs, buttons and textareas. Other elements, including `select`, `template` and `noscript`, are rejected conservatively because their parsing rules can change form boundaries. Comments and declarations are also rejected inside retained demos. Unmarked owner forms may use IDs, external controls, `select`, `template` and `noscript`. The starter verifier continues to check configured identity, metadata, indexing policy, sitemap, offline page digests/fallback, bundled font delivery and retained notices. Its regression suite uses disposable fixtures instead of requiring your application to keep the sample content.

Static HTML must remain byte-identical to selected build output. _headers supplies no-transform on compatible static hosts; host Functions and other serving products require equivalent policy. Hosted exact-byte and fresh install/offline/reconnect checks remain NOT RUN. Local browser acceptance is not deployment approval.

Upstream template/library code and original neutral examples are MIT OR Apache-2.0; the application package remains UNLICENSED. Retain packaged OFL font notices and Workbox MIT notices. Private content/history and producer qualification infrastructure are not part of this starter.

## Upgrading shared libraries

Use the [copyable delivery and source checks](UPGRADING.md) to verify archive/lock/installed bytes and the recorded offline producer comparison before an upgrade. The offline comparison records an independently checked commit/tree and its manifest packaging difference; it does not establish the archive's original packing commit. The commands use an optional producer checkout for provenance auditing, while normal application builds remain standalone.

Preserve your chosen application terms, scoped template notices and OFL font notices, and upgrade each library independently. For a bundled candidate, replace its exact vendor archive, dependency path and lockfile; update STARTER-DELIVERY.json with the reviewed archive path, SHA256 and version. Run `npm ci --ignore-scripts`, `npm run verify:licenses`, `npm run test:licenses`, `npm run check`, `npm run build`, `npm run verify:starter` and `npm run test:starter`, using the same preview/production environment for build and verification.

After an explicitly approved registry release exists, replace a library's file dependency with its exact published version and regenerate package-lock.json. Future registry upgrades need only the exact version and lockfile updates; historical bundled delivery receipts stay unchanged. The license guard requires the installed version to equal that exact pin and retains the library's MIT OR Apache-2.0 notices. Regression fixtures use installed candidate bytes to test registry mode; they do not demonstrate or perform npm publication.

Offline revisions follow emitted output digests: a package version change alone may leave output and worker revision unchanged. Compare generated worker/output before deploying, then verify natural activation, offline reading and reconnect on the actual host. To roll back, restore the prior dependency/lock and matching bundled receipt/archive when applicable, rebuild and review output. Deployment or DNS rollback cannot guarantee rollback of already controlled browser clients; retain the lifecycle and hosted acceptance gates.

Update libraries when a relevant fix or feature is needed; versions need not be leveled across different libraries or consumers. This starter retains its qualified AstroMache 0.2.6 navigation/offline default; the 0.2.7 Article geometry repair does not require an upgrade here.
